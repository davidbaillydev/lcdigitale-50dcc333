- Kitchen Android app ("LC Cuisine") is a Capacitor shell loading the published platform site named by server.url (/espace) in capacitor.config.json, with allowNavigation ["*"] so every redirect stays inside the app instead of failing on an absent browser; android/app/src/main/res/layout/activity_main.xml must stay free of any <WebView> tag because BridgeActivity inflates Capacitor's own layout and an empty one blacks the screen; cleartext and mixed content are allowed for local printers, with backgroundColor matching the brand's dark surface. Native features go through the custom LcKitchen plugin (android/.../LcKitchenPlugin.java) registered with @capacitor/core in src/lib/native-kitchen.ts, retaining window.Capacitor as a fallback and returning null in browsers/SSR; raw TCP printing is restricted to private LAN addresses; APK built by .github/workflows/android-cuisine-apk.yml. MainActivity warns when Android System WebView is older than 111 (site needs modern Chrome). Why: Capacitor 7 detects the native plugin without the legacy Plugins object and no third-party print bridge is needed.
- Borne shares the Android Java namespace/plugin with Cuisine but builds with -PlcBorneApp=true, a distinct applicationId and capacitor.borne.config.json staged only in its isolated workflow; BuildConfig.IS_KIOSK forces immersive/keep-awake even when web code requests off. Why: both apps can coexist and share direct LAN ESC/POS without changing Cuisine's default build.
- The /borne hub stores only validated slug/kiosk identity after server PIN verification; existing PIN-gated staff settings can reset that identity without deleting queues, licences or printer settings. Why: setup is device-local, declared kiosks remain server-controlled, and no PIN or payment capability is persisted.
